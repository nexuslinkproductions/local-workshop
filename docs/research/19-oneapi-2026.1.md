# 19 — oneAPI 2026.1 root-free install + second llama.cpp SYCL engine

**Status: installed, built and verified.** Intel oneAPI 2026.1 (DPC++/C++ compiler,
oneMKL, oneDNN, TBB) installed **root-free** side by side with the existing 2026.0
install, and a second SYCL engine built against it. No benchmark and no model load
were run — the GPU is owned by the testing lane.

Why: 2026.1 reportedly gives much faster SYCL **prompt processing**, which is the
bottleneck the 2026.0 build was stuck behind.

## 1. The claim

### 1a. llama.cpp's own doc (verbatim, `docs/backend/SYCL.md` §News, L55–57)

```
- 2026.09
  - Update the CI build environment for oneAPI 2026.1 (unified oneAPI Toolkit). oneDNN is removed from the Deep Learning Essentials package in 2026.0, so the CI now uses the oneAPI Toolkit installer which still includes oneDNN.
  - oneAPI 2026.1 improves the SYCL build performance: measured with the same code on Arc B570, prompt processing 1331 vs 434 t/s (3.1x) vs the 2025.3-based release build.
```

Same numbers, with the measurement context, in the upstream release note
[llama.cpp b11243](https://github.com/ggml-org/llama.cpp/releases/tag/b11243)
(PR #29273, *"ci : update the oneAPI toolkit to 2026.1"*):

> Measured with the same code (b10899) built with oneAPI 2026.1 vs the 2025.3-based
> release build on Arc B570: prompt processing 1331 vs 434 t/s (3.1x), token
> generation 50.1 vs 45.3-48.0 t/s.

**Read the comparison carefully:** the 3.1× is **2026.1 vs the 2025.3-based release
build**, not vs 2026.0. Our previous engine (research/11) was built with 2026.0, so
the gain we should expect here is the 2026.0→2026.1 delta, which is a subset of that
3.1×. The two comparisons are not the same claim.

### 1b. What Intel's release notes say changed (2026.1)

`docs/backend/SYCL.md` L286–288 now lists **2026.1** as a *verified release* (it was
2025.3.3 before), and L274 documents the packaging change:

> With the 2026.0 release, the Intel® oneAPI Base toolkit and the HPC toolkit are
> combined into the **Intel® oneAPI Toolkit**, and **oneDNN is removed from the
> Intel® Deep Learning Essentials** package (oneDNN is distributed separately since
> then). The **Intel® oneAPI Toolkit** includes oneDNN until 2027.0.

- **oneAPI Toolkit 2026.1** (ID 918369, rel. 2026-07-07) — *"improves performance and
  scaling of AI and HPC workloads through targeted optimizations across libraries and
  runtimes … initial enablement for Intel Xe3-based GPUs and deeper hardware
  awareness that helps map workloads more efficiently to GPU architecture."* The
  **Battlemage-specific** line is in the oneCCL notes: *"Custom reductions optimized
  specifically for Battlemage architecture deliver better performance."*
- **DPC++/C++ Compiler 2026.1** (ID 852942, rel. 2026-07-07) — *"Reduced SYCL runtime
  and library overhead over Unified Runtime (UR), improving: Kernel submission
  latency / Runtime throughput / Overall application startup time"*; also *"Extended
  sycl_ext_intel_device_info … for Intel GPUs based on Xe architecture"* and the
  compiler *"no longer forces preserve-sign denormal flushing by default for
  SYCL/OpenMP offload device compilation."* (Prompt processing is a GEMM/dequant
  pipeline, so kernel-submission and UR overhead are the plausible levers.)
- **oneMKL 2026.1** (ID 918369-family) — *"Introduced initial support for Intel GPUs
  that are based on Intel Xe3P microarchitecture"*, *"Improved the performance of
  lapack::orgqr for all architectures of Intel GPUs."*

No Intel note claims the 3.1× figure; that number is llama.cpp's measurement. Treat
the 3.1× as llama.cpp's, and the mechanism as UR/kernel-submission overhead + library
tuning, not a documented single feature.

## 3. Root-free install (no sudo anywhere)

Arch's `extra/` only carries 2026.0, so 2026.1 came from Intel's own offline
installer. It supports silent, non-root, custom-dir installs.

**Installer** (URL taken from Intel's oneAPI-CI, which pins the exact same artifact):

```
mkdir -p ~/intel/installers
curl -sSL --retry 3 -o ~/intel/installers/intel-oneapi-toolkit-2026.1.0.192_offline.sh \
  https://registrationcenter-download.intel.com/akdlm/IRC_NAS/33cb2a22-ddf1-4aa9-8d68-1f5a118acaf2/intel-oneapi-toolkit-2026.1.0.192_offline.sh
```

`--list-components` on that package (only the four we need):

```
intel.oneapi.lin.dpcpp-cpp-compiler 2026.1.0+235   Intel® oneAPI DPC++/C++ Compiler   (deps: dpl)
intel.oneapi.lin.mkl.devel          2026.1.0+236   Intel® oneAPI Math Kernel Library
intel.oneapi.lin.dnnl               2026.0.1+55    Intel® oneAPI Deep Neural Network Library (deps: tbb.devel)
intel.oneapi.lin.tbb.devel          2023.1.0+151   Intel® oneAPI Threading Building Blocks
```

**Install** — side by side, `~/intel/oneapi` untouched:

```
sh ~/intel/installers/intel-oneapi-toolkit-2026.1.0.192_offline.sh \
  -a --silent --eula accept \
  --install-dir /home/nexuslink/intel/oneapi-2026.1 \
  --log-dir /home/nexuslink/intel/logs \
  --components intel.oneapi.lin.dpcpp-cpp-compiler:intel.oneapi.lin.mkl.devel:intel.oneapi.lin.dnnl:intel.oneapi.lin.tbb.devel
```

Result: `Installation has successfully completed`, exit 0. Layout:
`compiler/2026.1`, `mkl/2026.1`, `dnnl/2026.0`, `tbb/2023.1`, `umf/1.1`, `tcm/1.5`,
each with a `latest` symlink, plus `setvars.sh`.

Two **spurious** installer warnings (both harmless on Arch):
- *"This machine uses operating system \"Unknown\". Compatibility issues may occur."* — Arch is not in Intel's supported-OS list.
- *"G++ package is not installed"* — false; `g++ (GCC) 16.2.1` is present and the build links fine.

**One real side effect on `~/intel/oneapi` (read this).** For a root-free run the
installer hardcodes its own bootstrap program dir as `[UserHome]/intel/oneapi/installer`
(see `~/intel/logs/bootstrapper.*.log`: *"Resolving … '[UserHome]/intel/oneapi/installer'"*),
which happens to sit inside the existing 2026.0 root. It added **only** that new
`installer/` subdir (105 MB of Qt installer files) and touched **no 2026.0 file** —
verified: `find ~/intel/oneapi -newermt "01:25" -not -path "*/installer/*"` returns
nothing, and the 2026.0 `icpx` still reports `2026.0.0 (2026.0.0.20260331)`. Left in
place deliberately (it is the installer's program dir; the offline `.sh` re-extracts
itself anyway, so deleting it only churns 105 MB). Remove it with
`rm -rf ~/intel/oneapi/installer` if the literal "don't touch" is required.

- `tbb/2023.1/lib/cmake/tbb/TBBConfig.cmake` uses `get_filename_component(_tbb_root

  so `libggml-sycl.so`'s `NEEDED libdnnl.so.3` resolves with no manual append.

## 8. Caveats for interpreting results

- **AOT is pinned to `bmg`.** `-DGGML_SYCL_DEVICE_ARCH=bmg` bakes a single AOT device
  image (no JIT fallback). If it ever proves device-incompatible, rebuild with the
  doc's plain four-flag command (drops AOT, keeps a JIT-capable `spir64` build).
- **oneDNN is still 2026.0.1** in the 2026.1 toolkit (`libdnnl.so.3.11`); only the
  compiler/MKL/TBB moved. So any measured gain is compiler/MKL/UR-side, not oneDNN.
- **ABI note (from the 2026.0 notes):** *"This is an ABI/API breaking release. All
  applications using earlier oneAPI SYCL runtimes must be rebuilt."* Our engine was
  built wholly against 2026.1, so it is self-consistent — but do **not** mix 2026.0
  and 2026.1 `LD_LIBRARY_PATH`s for one binary.
- **Do not benchmark yet** — the GPU is owned by the testing lane. When it frees up,
  A/B `llama-bench -p 512` (or the recipe in research/10) on this engine vs
  `llama.cpp-sycl-tip`, same model, same flags; that isolates the toolchain delta.
